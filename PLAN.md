# Личные финансы и кредитные карты на Android

> Исследование до перехода на локальный импорт PDF. Текущие возможности и запуск описаны в README.md.

Обновлено 22 ноября 2026 года. Первая цель — автоматическое обновление операций и обязательств по кредиткам без банковских пушей и регулярной ручной выгрузки. Стек — Kotlin и Jetpack Compose, как в [a-ir-remote](/Users/belowevolve/code/a-ir-remote/README.md). Начинаем с проверки источника данных, затем делаем приложение вокруг подтверждённого доступа. Серверный компонент и веб-панель отложены.

## План разработки

1. **Проверить официальный доступ до начала разработки экранов.** Начать параллельно с Альфы и ВТБ, где есть розничные пилоты. По Ozon отдельно выяснить наличие программы для сторонних поставщиков услуг. Для каждого банка запросить условия допуска, схему согласия с правами только на чтение, тестовый контур и список поддерживаемых продуктов. Критичные вопросы — может ли участвовать частный разработчик, допустим ли Android-клиент без серверного секрета и какие поля реально приходят по личной кредитке. Ассоциация ФинТех описывает процедуру подключения организаций через испытания и сертификаты. Публичные примеры API счетов физлиц позволяют проверить интеграцию на синтетических данных. Доступ к реальному счёту подтверждается отдельно. [Процедура подключения](https://wiki.openbankingrussia.ru/guides/joining-the-environment-of-open-banking-interfaces), [песочница](https://www.fintechru.org/directions/pilotirovanie-initsiativ/), [документация тестового API](https://api.openbankingrussia.ru/accounts-pe-v2.0.0/)
2. **Проверить одну кредитку сквозным сценарием.** Проверить историю операций и обновление после повторного открытия приложения. Для минимального платежа и грейса отдельно получить дату, сумму и остаток к оплате. Проверить состояние после частичного платежа, полного зачёта, смены расчётного периода и отзыва доступа. Зафиксировать время обновления и поведение при недоступности банка. Источник годится для операций и без кредитных полей. Источник годится для автоматического отключения напоминания, когда возвращает свежий статус конкретного обязательства. Доступность хотя бы одного полезного канала определяет объём первой сборки.
3. **Сделать Android-клиент.** Счета, операции, статистика по категориям и блок «К оплате». Обновление после разблокировки одним открытием приложения. Подключения сменные и независимые по банкам. У каждого источника видна дата обновления и ошибка доступа. Новая синхронизация подтягивает пропуски с использованием стабильных банковских ID, отмечает исправления и сохраняет категории пользователя. Погашение кредитки со своего счёта учитывается как перевод между своими счетами, покупка как расход, комиссии и проценты отдельными расходами.
4. **Добавить оповещения и пройти личный пилот.** Отслеживать минимальный платёж и грейс как отдельные обязательства с расчётным периодом, источником, датой и остатком. За календарный день до срока показывать локальное уведомление. Смахивание доступно на Android 14 и новее. Статус в блоке «К оплате» закрывается после подтверждения зачёта банком или явной ручной сверки. Пополнение, частичное погашение и отсутствие свежих данных сами по себе статус не закрывают. По активной кредитке проверить полный цикл на реальных данных, которые остаются у пользователя. [Уведомления Android 14](https://developer.android.com/about/versions/14/behavior-changes-all#non-dismissable-notifications), [расписание напоминаний](https://developer.android.com/develop/background-work/services/alarms)

Если на первом этапе доступ подтвердится только для истории, можно выпустить автоматический учёт для поддерживаемых банков и честно обозначить кредитки, которые требуют сверки. Если промышленного доступа для частного приложения нет вообще, полноценную автоматизацию считаем заблокированной доступом к данным. Автоматическое письмо Альфы можно проверить отдельно как ограниченный сценарий по минимальному платежу.

## Модель безопасности

- Вход и выдача согласия происходят на стороне банка. В приложении используются только ограниченные банковские токены, когда банк поддерживает такой доступ. Для нативного публичного OAuth-клиента применяем внешний браузер и PKCE, если этот режим предусмотрен банком. Если банк требует конфиденциальный серверный клиент или сертификат инфраструктуры, это отдельная архитектурная развилка. Такой секрет в APK не помещаем. [OAuth для нативных приложений](https://www.rfc-editor.org/rfc/rfc8252.html)
- Финансовые данные и токены на телефоне храним в зашифрованном SQLCipher. Случайный ключ хранилища защищён парольной фразой с Argon2id и отдельной обёрткой Android Keystore с сильной биометрией. Для смены отпечатка предусмотрен вход по парольной фразе. Исключаем данные из Auto Backup и системного переноса. Перенос на другой телефон — через явную зашифрованную копию. Сетевые запросы клиента идут только к разрешённым источникам. [SQLCipher для Android](https://github.com/sqlcipher/sqlcipher-android), [Argon2id](https://www.rfc-editor.org/rfc/rfc9106.html), [биометрия Android](https://developer.android.com/identity/sign-in/biometric-auth), [Android Auto Backup](https://developer.android.com/identity/data/autobackup)
- Уже рассчитанный сигнал работает при закрытом хранилище. Системе для него передаём время и непрозрачный идентификатор. Уведомление скрывает банк, карту и сумму. При закрытом хранилище подтверждение оплаты поступит в приложение в момент следующей синхронизации после разблокировки. После перезагрузки телефона или принудительной остановки расписание восстанавливается при ближайшей разблокировке приложения. Если связь пропала, показываем время последней проверки и сохраняем известное обязательство открытым. [Планирование Android](https://developer.android.com/develop/background-work/services/alarms), [принудительная остановка](https://developer.android.com/about/versions/15/behavior-changes-all#package-stopped-state)

## ВТБ — первая проверка

Запущены выбранные маршруты опубликованного эмулятора Bank-in-a-Box на коммите `ffa454577b61d861738635d3078723c93e7429da`. Тестовый клиент, счёт, кредитная карта и покупка созданы в отдельной временной базе. HTTP-вызовы отправлены напрямую в обработчики внутри процесса. IP-сокеты отключены для запуска, база доступна только через локальный Unix-сокет. База остановлена по завершении. Реальный счёт, учётные данные банка и Android по ADB для проверки не использовались. [Описание стенда командой ВТБ](https://habr.com/ru/companies/vtb/articles/985546/), [исходники проверенной версии](https://github.com/GalkinTech/bank-in-a-box/tree/ffa454577b61d861738635d3078723c93e7429da)

| Фактический вызов | Код | Результат |
| --- | --- | --- |
| `GET /accounts` без токена | `403` | Эмулятор отклонил чтение без входа. |
| `POST /auth/login` | `200` | Эмулятор выдал локальный токен вымышленного клиента. Значение токена в журнал не выводилось. |
| `GET /accounts` | `200` | Один тестовый счёт, включая идентификатор, тип и валюту. |
| `GET /accounts/acc-1/balances` | `200` | Две записи баланса с суммой, типом и временем. |
| `GET /accounts/acc-1/transactions` | `200` | Одна покупка с идентификатором операции, суммой, датой проводки и статусом. |
| `GET /cards` | `200` | Одна тестовая кредитка. Ответ содержит баланс счёта, статус карты и лимиты трат. Даты и суммы минимального платежа, условия текущего грейса и зачёт отсутствуют. Полный номер карты присутствует в тестовой схеме, его не следует сохранять для учёта. |
| `GET /product-agreements` | `500` | Ошибка локального обработчика, который обращается к неопределённой переменной. Опубликованная модель договора содержит сумму, статус и даты договора. Полей текущего платежа в ней нет. [Исходник обработчика](https://github.com/GalkinTech/bank-in-a-box/blob/ffa454577b61d861738635d3078723c93e7429da/api/product_agreements.py#L41) |

Токен эмулятора выдан встроенному тестовому клиенту. Проверка показывает работу чтения и требование входа в локальном эмуляторе. Банковское согласие только на чтение и его отзыв на этом этапе не проверялись. ВТБ описывает размещённый стенд 2025 года как доступный участникам завершившегося хакатона. Открытый способ получить новый доступ к розничному тестовому контуру ВТБ не подтверждён. Общий стенд АФТ документирует чтение счетов за авторизацией. [Хакатон ВТБ](https://apihack.vtb.ru/), [контракт розничного API АФТ](https://api.openbankingrussia.ru/accounts-pe-v2.0.0/)

Для продолжения нужен ответ ВТБ на два вопроса. Дают ли независимому Android-приложению доступ к личным счетам и операциям с отзывным согласием только на чтение? Возвращает ли этот доступ по кредитке сумму и дату минимального платежа, сумму и дату для сохранения грейса и остаток конкретного обязательства после зачёта? Для уточнения достаточно описания полей, условий допуска и тестового контура. Данные реального клиента для этого не требуются.
